## 2. 一句话说明

团队内部使用的亚马逊运营协作平台：**人在 TradeQuill 桌面应用里分配任务、做决定；任意 AI Agent 通过标准接口接入，负责取数、分析、写初稿和给建议；所有费用按真实报价和生效期精确计算；结果同步到团队的在线协作文档。**

## 4. 共同原则

1. **人做决定，Agent 干活。** Agent 取数、分析、写初稿、给建议；留 / 砍、调价、下单补货、发货都由人确认。
2. **规则在平台里，不在提示词里。** 筛选标准、成本公式、费率、补货参数、报告模板都由平台存储、计算和校验。Agent 只提交原始数据和分析文字，关键数字由平台计算。
3. **任何数字都有出处。** 每条数据记录来源、工具、时间、哪个 Agent；每个费用记录用了哪张费率表、哪个生效期。
4. **两头可插拔。** 数据从哪来、结果写到哪去，都通过适配层接入。
5. **先排除，再挑选。** "7 盲 2 傻"产品在选品初筛直接排除或标红。
6. **省着用次数。** 付费数据源做缓存、去重、预估和限额。
7. **库存是钱。** 每个补货、发货建议都同时给出压款金额和预计仓储费；宁可多发几批，也不让货在仓库里等。【新增】
8. **学打法，不抄内容。** 模仿竞品的定价节奏、促销方式、关键词和卖点方向；不复制对方图片、文案，不碰商标和专利，不做违规刷评。【新增】

  │ 任务看板 · 规则与参数 · 来源追溯 · 操作日志 · 用量管理 · 审批          │
  ├───────────────┬──────────────────────────┬──────────────────────┤
  │ Agent 接入层   │ 数据源适配层                │ 文档输出适配层          │
  │ （MCP / API）  │ 卖家精灵 · 1688 · 货代报价    │ 腾讯文档（第一期）      │
  │               │ 亚马逊 SP-API（上架后）· 预留 │ 自研文档（预留）        │
  └───────────────┴──────────────────────────┴──────────────────────┘
          ▲ 每台电脑上的 TradeQuill 本地助手（MCP）
  Claude / Codex / DeepSeek Agent …

  团队共享数据：香港服务器上的数据库 + API（只存数据，不跑 AI） ⇄ 各成员电脑上的 TradeQuill

**数据流向：**

- 选品定款时，把对标竞品清单交给 03，把产品尺寸重量、采购价、起订量、生产周期交给 04。
- 03 产出"竞品打法时间轴"和"目标销量曲线"（参考手册 4.8 的 80 天节奏），作为 04 上架前的销量预测。
- 上架后，04 改用自家店铺的真实销量和库存；03 发现竞品断货、降价、大促时，提醒 04 调整预测。
- 01 和 04 都调用 02 计算费用；02 的报价或费率更新时，自动重算受影响的选品和补货计划。

## 8. 平台公共功能

### P1 任务看板

- 每个模块有自己的看板列（见各模块文档），共用一个看板页面，可按模块筛选。
- 多人实时同步，能看到"谁正在看 / 改哪一条"。

### P2 审批与建议

- Agent 给出的建议（调价、促销、补货下单、发货批次）统一进入「待处理建议」，人逐条采纳 / 修改 / 驳回并写理由。
- 采纳记录用于事后复盘：这条建议执行后，销量、排名、利润、库存发生了什么变化。

### P3 Agent 接入

- 每台电脑上的 TradeQuill 本地助手提供 **MCP 服务**，Agent 连本机即可；不对公网开放接口。
- 每个 Agent 有独立身份（名称 + 接入凭证），可单独停用；所有调用记日志。
- 各模块的接口能力见各模块文档。

### P4 数据源适配层

| 数据源                    | 阶段   | 接入方式                                   | 提供的数据                                                                                 |
| ------------------------- | ------ | ------------------------------------------ | ------------------------------------------------------------------------------------------ |
| 卖家精灵                  | 第一期 | 官方 MCP                                   | 选品数据、关键词、竞品销量 / 价格 / 排名趋势、评论（MCP 不含商标查询，见 01 第 7 节）      |
| 1688                      | 第一期 | 【待调研】                                 | 采购价、起订量、阶梯价、发货周期                                                           |
| 货代报价                  | 第一期 | Excel / 图片 / PDF / 微信文字导入（见 02） | 头程价格、时效、起运量                                                                     |
| **亚马逊 SP-API**         | 第二期 | 官方接口，店铺授权                         | **自家订单与销量、FBA 库存（可售 / 在途 / 预留）、货件状态与签收上架时间、费用、库容限制** |
| 亚马逊广告 API            | 后续   | 官方接口                                   | 广告数据                                                                                   |
| Keepa / Sorftime / SIF 等 | 预留   | 适配器                                     | 竞品价格、优惠、库存变化的补充或交叉验证                                                   |

### P5 文档输出适配层

- 平台是数据主源，在线文档是副本：平台 → 文档自动同步，文档里的修改不回写。
- 第一期同步到腾讯文档：选品简化表、选品报告、竞品每日表、补货计划表。
- 【待调研】腾讯文档开放接口能否自动建表、写行、更新单元格。

### P6 追溯、日志、用量

- 每个数字可点开查看来源；成本数字可看到用了哪张费率表、哪个生效期。
- 操作日志记录谁（人或 Agent）在什么时间改了什么。
- 卖家精灵次数：实时显示已用 / 剩余，任务前预估，超限暂停；同一数据在有效期内优先用缓存。竞品每日跟踪会持续消耗次数，单独设每日上限（见 03）。

### P7 在 TradeQuill 里和 Agent 对话【已确认 2026-11-14：要能直接对话】

- **对话窗口在哪：** 亚马逊运营的每个页面右侧都能打开对话栏；Agent 知道你当前在看哪个产品、哪份报告、哪个补货批次，不用再复制粘贴。
- **能做什么：**
  - 问数据："这款旺季空运毛利多少？""竞品 B 上周做了什么？"
  - 让平台算："售价改成 $14.99，海运快船，ROI 是多少？"（数字由平台的成本引擎算，Agent 只负责解释）
  - 派活："帮我把家居收纳类目初筛一遍" → 自动在看板上建任务，耗时长的任务由在线电脑上的 Agent 慢慢跑，跑完通知你
  - 写初稿：报告段落、模仿建议、补货说明
- **不能直接做：** 改价格、确认补货下单、确认报价生效、删除数据、往腾讯文档以外的地方发东西。对话里只能生成"建议卡片"，人点"确认"才执行，和 P2 审批走同一套流程。
- **不编数字：** 回答里的数字必须来自平台查询或计算，并能点开看来源；查不到就说查不到。
- **用哪个 AI：** 对话用的模型在 TradeQuill 的 AI 服务设置里配置（可选 Claude、DeepSeek、OpenAI 兼容等），不绑定一家；Claude Code、Codex 等外部 Agent 仍通过本地 MCP 接入，二者用同一套平台能力。
- **对话记录：** 默认只有自己看得到；可以一键"附到任务 / 报告"让团队看到。
- **用量：** 显示每次对话消耗的模型费用和卖家精灵次数；超出每日上限时提醒。

## 9. 在各自电脑上运行【已确认：Agent 在各自电脑上】

### 9.1 要分清"Agent 在哪跑"和"数据放在哪"

- **Agent 在各自电脑上跑**：本地助手就是 TradeQuill 的一部分，Agent 通过它领任务、查数据、提交结果；卖家精灵、SP-API 等密钥保存在电脑的系统钥匙串里，不写进普通文件和日志。
- **团队共享的数据放在云端数据库**，否则 2–5 个人没法实时看到同一个看板、同一份报告。云端**只存数据、不跑 AI**，费用远低于 24 小时跑 Agent 的服务器；腾讯文档继续作为展示副本。【随方式 B 确认】云端用团队自购的香港服务器，跑 Postgres 和一个薄 API【已确认 2026-11-19，见[技术方案](技术方案.md) 5.3】。

### 9.2 电脑关机时怎么办

| 任务                | 做法                                                                                                     |
| ------------------- | -------------------------------------------------------------------------------------------------------- |
| 竞品每日快照（03）  | 早上第一个开机的成员电脑领走当天任务；当天谁都没开机就跳过，平台标记"当日无数据"，**不事后编造当天数据** |
| 补货每日重算（04）  | 开机后立即补算；如果离"最晚发出日期"只剩 3 天以内，补算后马上提醒                                        |
| 选品任务（01）      | 按看板排队，谁的电脑在线谁领                                                                             |
| 断货 / 补货紧急提醒 | 只在开机时能发出；【建议】提醒同时写进腾讯文档或手机能看到的地方                                         |

- 同一个任务加锁，两台电脑不会重复跑、不会重复扣卖家精灵次数。
- 看板上显示每台电脑的在线状态和上次运行时间。

## 10. 与 TradeQuill 结合【已确认：方式 B，TradeQuill 当桌面端】

`~/Code/TradeQuill` 现状（2026-11-14 读取）：

- Windows / macOS 桌面应用（Tauri + React），数据存在本机 SQLite，定位是**个人单机**，不做云同步。
- 已有：客户、询盘、报价、样品、跟进日历；**产品档案（起订量、交期）**和本地知识库（资料导入、版本、检索）。
- 已做过一份电商数据接入研究：亚马逊 SP-API、Keepa 等的能力和授权边界，结论之一是"监控只在应用运行且电脑清醒时执行"——和本项目"Agent 在各自电脑上"的决定一致。
- AI 能力（Epic #17）正在规划，尚未交付。

**能直接复用的：** 桌面应用框架、产品档案（起订量 / 交期正好是 04 补货要的供应商数据）、知识库（可放手册、货代报价原件）、SP-API 接入研究。系统钥匙串保存密钥目前还没有实现，要新做（2026-11-19 核对，见[技术方案](技术方案.md)第 2 节）。

**主要冲突：** TradeQuill 是"一个人、一台电脑、数据不出本机"；本项目是"2–5 人实时协作"。结合方式不同，冲突的处理方式也不同：

| 方式                                 | 做法                                                                                                     | 好处                                                           | 代价                                        |
| ------------------------------------ | -------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------- | ------------------------------------------- |
| A. 先独立做，留好接口                | 本平台先独立开发；"本地助手"按 TradeQuill 能嵌入的方式设计；产品 / 供应商数据定义成可互相导入导出的格式  | 现在不受 TradeQuill 单机边界限制，进度最快；以后结合不推倒重来 | 结合前两边各维护一份产品资料                |
| **B. TradeQuill 当桌面端【已选】**   | TradeQuill 新增"亚马逊运营"模块，作为每个成员电脑上的本地助手和操作界面；团队共享数据走 9.1 的云端数据库 | 一个桌面应用干所有事；完全符合"在各自电脑上跑"                 | TradeQuill 要放开"不做云同步"的边界，改动大 |
| C. 全部做进 TradeQuill，不做实时协作 | 每人一份本地数据，靠腾讯文档或导出文件交换                                                               | 不需要任何云端                                                 | 放弃实时协作看板，多人容易数据不一致        |

### 10.1 方式 B 的落地规则【建议】

- **个人数据和团队数据分开。** TradeQuill 原有的客户、询盘、报价、样品、跟进仍只存在本机，不上传；只有"亚马逊运营"模块的数据（选品、费率、竞品、补货、任务）同步到云端，团队共享。设置页明确显示哪些数据会同步。
- **TradeQuill 的边界要改。** 它现在写明"第一版无 AI、无云同步、个人单机"。方式 B 需要在 TradeQuill 里正式记录新边界：新增团队工作区、登录、云同步（仅亚马逊模块）、本地 MCP 服务供 Agent 接入。这些改动按 TradeQuill 自己的流程（GitHub Issues、设计规范、验收记录）提需求和交付。
- **离线也能用。** 断网时可以看本地缓存、录入数据；联网后同步。两人同时改同一条记录时保留双方版本并提示，不静默覆盖。
- **密钥留在本机。** 卖家精灵、SP-API、1688、腾讯文档的授权存在各自电脑的系统钥匙串里，不上传云端（团队共用的账号由负责人分别授权到需要的电脑上）。
- **界面跟 TradeQuill 的设计规范走。** 左侧导航新增"亚马逊运营"入口，下面放看板、选品、物流费率库、竞品跟踪、补货计划；现有原型图的页面内容不变，外观之后按 TradeQuill 的样式重画。
- **与 TradeQuill 现有 AI 规划的关系。** TradeQuill 的 AI 规划（GitHub Epic #17）写明"不搭建通用 Agent 平台""个人单机、无自动云同步不变"，而本项目需要团队同步、对话式 Agent 和本地 MCP 接入，两者冲突，要在 TradeQuill 里更新这条边界。可复用：#18 共用 AI 服务配置（对话模型就在这里配）；#25 竞品分析可与 03 合并或复用来源材料。
- **可复用：** 产品档案的起订量 / 交期直接给 04 补货用；知识库存放运营手册、货代报价原件；已有的电商数据接入研究（SP-API 授权、限流、数据保存期限）作为 SP-API 接入的依据。
