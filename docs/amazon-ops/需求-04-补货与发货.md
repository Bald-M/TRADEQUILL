## 1. 为什么要做【已确认】

- FBA 仓储费贵，**不能一次把一堆货发进 FBA**。
- 补货时间要跟着销量动态调整，由 AI 算出"大概什么时候补、补多少"。
- 入仓上架要时间，要提前算进去；也不能让货在仓库里干等。
- **动销率要高**：每批货尽快卖完。
- **前期要严控成本**：第一款产品启动资金只有 5 万元。

手册给的依据：

- 发货周期 = 生产周期 + 质检时间 + 物流时间 + 亚马逊上架时间（例：7 + 7 + 40 + 7 = 61 天，即 FBA 库存还够卖 61 天时就要下单）。
- 补货量：月度补货不低于月销量的 1.2–1.5 倍；周度补货不低于周销量的 1.2 倍。
- 打造期最忌讳断货；"舍不得备货"会让排名卡住（手册 4.7 案例）。
- 讲师团队规则：**单批库存入仓上架后 3 个月内必须卖完**，未卖完的从第 4 个月起每月按剩余库存金额折旧 10%（手册 6.12）。
- 库存原则：不压货、不断货、低成本运输。

## 2. 核心思路

**大货不进 FBA，FBA 里只放"够卖到下一批到仓"的量再加一点安全量。**

```
  供应商发货 → 自己仓库（国内）：到货验收；散货在这里贴标、包装、装箱
                     │  按节奏分批发出，没发的留在自己仓库
        ┌────────────┼────────────┐
      空派（快、贵）   海运快船        海运慢船（慢、便宜）
     救急 / 首批破零   主力补货        计划性大批
        └────────────┼────────────┘
                     ▼
           FBA 签收 → 上架（要时间，按历史实际天数算）
                     ▼
        FBA 可售库存：保持在「下限 ~ 上限」之间
        下限：≥ 28 天供货（低于此收低库存水平费，也容易断货）
        上限：【建议】≤ 60 天供货，旺季（10–12 月）按仓储费单独设
```

两头都要防：

- **太多**：仓储费、旺季 3 倍仓储费、超龄附加费、仓储利用率附加费、压款、IPI 下降、库容受限。
- **太少**：断货掉排名、低库存水平费、空运救急成本高。

【已确认】采购的货先到自己仓库，要发的批次直接发到 FBA 仓入仓上架，没发的留在自己仓库；不用海外仓 / AWD。部分采购是散货，要先在自己仓库贴标（见第 7 节）。

## 4. 计算规则（平台计算，Agent 只做解释和调整建议）

### 4.1 销量预测

- 上架后用最近 7 / 14 / 30 天销量加权，**剔除断货天**（断货天的真实需求被低估）。
- 叠加：季节系数（卖家精灵类目趋势）、计划调价和优惠券（来自 03 已采纳的建议）、竞品断货或大促信号。
- 输出区间：正常、偏乐观、偏保守三条线；补货下限按偏乐观算（防断货），补货上限按偏保守算（防压货）。

### 4.2 补货时间点

```
总提前期 = 生产 + 质检 + 到自己仓库 + 贴标包装（散货才有） + 送到货代 + 头程（按渠道，取较慢情况） + 签收到上架
可售天数 = （FBA 可售 + 已在途且预计在断货前上架的数量）÷ 预测日销
当 可售天数 ≤ 总提前期 + 安全天数 时 → 必须下单 / 发货
```

- 安全天数默认 7 天【建议】，可按产品设置。
- 自己仓库里已有"可发货"的现货时，提前期只算送货代、头程和上架；只有"待贴标"的散货时，再加上贴标包装时间。
- 每个渠道单独算"最晚发出日期"，看板上显示倒计时。

### 4.3 每批发多少

- 目标：这一批上架后，FBA 可售保持在 **28 天 ≤ 供货天数 ≤ 上限天数** 之间。
- 每批量 ≥ 渠道起运量（02 报价里的最低计费重量 / 体积），否则合并或改渠道。
- 每批量 ≤ 当月库容剩余。
- 每批预计"上架后卖完天数"必须 ≤ 90 天（3 个月卖完规则）；超过则拆小或推迟。
- 平台对每个候选方案用 02 计算：头程 + 入库配置费 + 每月仓储类费用 + 资金占用，取单件完整成本最低且不违反上面条件的方案。

### 4.4 渠道组合

- 默认组合【建议】：首批用空派小批量破零；随后海运快船做主力；销量稳定后加慢船降成本。
- 断货风险出现时，比较三个应对办法的代价，给人选择：
  1. 空派加急一批（多出的运费）；
  2. 小步提价放缓销量，撑到下一批到仓（手册 4.10："小步快跑"提价，在断货前赚取超额利润）；
  3. 接受短期断货（损失的利润 + 排名风险）。
- 旺季（10–12 月）：提醒提前发货赶在入仓高峰前；同时提示旺季在库成本是淡季 3 倍。

### 4.5 资金曲线

- 按天模拟钱的进出：采购定金 / 尾款、头程付款、关税、亚马逊回款（默认每 14 天一次，扣除佣金、配送费、仓储费、广告）。
- 显示**资金占用最高点**和日期；超过预算（第一款 ≤ 5 万）直接标红并给出替代方案（减少首批、增加批次、改用更便宜渠道）。

## 5. 动销率与库存健康

| 指标             | 定义                                         | 默认警戒线【建议】                                         |
| ---------------- | -------------------------------------------- | ---------------------------------------------------------- |
| 可售天数         | FBA 可售 ÷ 预测日销                          | < 28 天标黄；< 总提前期标红                                |
| 动销率（30 天）  | 近 30 天售出 ÷ 近 30 天平均在库              | 低于 1.0（即一个月卖不完平均库存）标黄                     |
| 批次库龄         | 按批次先进先出，计算每批已上架天数和剩余件数 | 60 天未卖完标黄；90 天标红；180 天前必须处理（超龄附加费） |
| 折旧后利润       | 第 4 个月起每月按剩余货值折旧 10%            | 用于判断该不该清货                                         |
| IPI / 库容使用率 | 卖家后台数据                                 | IPI 接近 400 或库容使用 > 80% 时提醒                       |

**滞销处理建议**（进入「待处理建议」）：降价、开优惠券、报秒杀、站外清货、移除回国或转海外仓、弃置。平台算出每种办法的总账（按边际成本和机会成本，不看沉没成本，手册 6.12），推荐亏损最小的一种。

## 6. 首批备货方案（第一期就要，在选品阶段算）

选品报告和定款时，平台自动生成一份首批方案，回答"这款产品启动要压多少钱、分几批发"。

**示意（数字仅说明格式，不是测算结果）：**

| 批次     | 下单 / 发出    | 渠道            | 件数                    | 预计上架 | 覆盖                     | 本批资金    |
| -------- | -------------- | --------------- | ----------------------- | -------- | ------------------------ | ----------- |
| 采购下单 | D-30           | —               | 1,500（全部到自己仓库） | —        | —                        | 定金 30%    |
| 第 1 批  | D-12           | 空派            | 150                     | D0       | 第 1–4 周（日均 3–6 单） | 货款 + 空运 |
| 第 2 批  | D-12           | 海运快船        | 350                     | 约 D+20  | 第 4–8 周（日均 10 单）  | 货款 + 海运 |
| 第 3 批  | 按实际销量触发 | 海运快船 / 慢船 | 动态                    | —        | 第 8 周后                | —           |
| 剩余     | 留在自己仓库   | —               | 动态                    | —        | —                        | 尾款        |

- 每一行的件数、日期由平台按 4.2–4.5 计算；Agent 写一段说明（为什么这样分批、最大风险是什么）。
- 和"一次全部海运进 FBA"的方案并排对比：仓储费、资金占用最高点、断货风险。

## 7. 自己仓库与贴标（新增）【已确认：部分采购是散货，需要贴标】

亚马逊要求每件商品贴上它分配的商品标签（FNSKU 条码），外箱贴货件箱标。工厂已贴好的货可以直接装箱，散货要在自己仓库处理。

**处理流程：** 到货验收（数量、外观、抽检） → 贴商品标签（有时还要套袋、贴"窒息警告"等提示标） → 按货件装箱 → 贴箱标 → 交给货代

**平台要做的：**

- 每个产品记录"供应商是否代贴标"。采购下单时提示：能让工厂贴就让工厂贴（通常更省事）。
- 自己仓库的库存分两种：**待贴标**和**可发货**。补货建议只把"可发货"算作马上能发的货。
- 补货建议确认后，自动生成**贴标任务**：贴哪个产品、多少件、最晚哪天贴完（= 最晚发出日期 − 1 天）；可下载标签打印文件（PDF）。
- 按每天能贴多少件估算贴标时间，并算进总提前期；件数大、时间紧时提前提醒加人手。
- 每天能贴多少件【暂不确定】：先按默认 200 件 / 天【建议，偏保守】估算，并多留 1 天余量；每次贴标完成后记录实际件数和用时，做满 3 次后自动改用实际平均值。
- 装箱单：每箱件数、箱数、箱子尺寸和重量，满足货代起运量和亚马逊单箱限制（手册 6.3）。
- 贴标包装费用（人工 + 标签 + 袋子 + 纸箱）按件计入成本（见 02 的"国内处理费"）。

**常见错误要拦住：** 标签贴错产品或变体、旧标签没盖住、条码打印不清。平台在贴标任务里显示产品图片和对应的标签号，贴完由另一人抽查后再标记"可发货"【建议】。

## 8. 每日运行（上架后，第二期）

1. 每天定时拉取 SP-API 销量、库存、货件状态。
2. 平台重算预测、可售天数、各渠道最晚发出日期、批次库龄。
3. 有变化时生成建议：「X 月 X 日前发出 N 件，走 XX 渠道」、「第 2 批已签收 9 天仍未上架，建议开 Case」、「第 1 批 75 天还剩 40%，建议开 15% 优惠券」。
4. Agent 写一句话解释原因（例如"近 7 天日均从 12 涨到 18，竞品 B 断货"）。
5. 人在「待处理建议」里确认；确认后平台生成发货清单（批次、件数、渠道、箱数），物流维护人发出后录入实际发出日期。

## 9. 看板状态【建议】

补货批次：`建议中 → 已确认 → 贴标包装中（散货才有） → 待交货代 → 运输中 → 已签收 → 已上架 → 售罄`

采购批次：`已下单 → 生产中 → 已到自己仓库 → 待贴标 / 可发货`

- 任一批次可进入"异常"：延迟、签收差异、上架超时、库容不足。

## 10. Agent 接口能力（MCP）

| 能力               | 说明                                                       |
| ------------------ | ---------------------------------------------------------- |
| 读取库存全景       | 各批次状态、可售天数、预测、资金曲线                       |
| 读取补货建议       | 平台算出的方案及计算依据                                   |
| 提交解释与调整理由 | 例如"下周有优惠券，预测上调 20%"；调整幅度超过阈值需人确认 |
| 试算方案           | 给定批次、渠道、件数，返回成本、资金曲线、断货 / 压货风险  |
| 报告异常           | 货件延迟、签收差异、上架超时                               |

Agent 不能直接下单、创建货件或改价格。
