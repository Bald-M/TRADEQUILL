# 产品、报价、订单与经营测算

本文记录 Issue #10–#16 的首版业务规则。三组实施方案已由用户于 2026-10-03 确认，见 [Epic 决策记录](https://github.com/Bald-M/TRADEQUILL/issues/10#issuecomment-5970353872)。历史客户工作流见 [客户与跟进](customer-workflow.md)，实际验证与未验证的平台见 [验收记录](validation.md)。

## 使用顺序

1. 在“产品与知识库”或“业务管理 → 产品、报价与订单”维护同一份产品档案，在后者建立供应商；产品可独立用于报价，无需先维护供应商。
2. 在产品或供应商详情关联供货资料。一个产品可由多家供应商供货，参考价格不覆盖产品通用资料。
3. 在“报价单”设置默认公司抬头，选品并填写数量、单价、有效期和贸易条款，保存后查看精确合计、MOQ 提示及中英双语报价预览，导出 PDF。
4. 从确定的报价版本生成订单草稿，补充承诺交付日期后确认订单。客户卡片也提供报价与订单入口。
5. 在订单中录入采购、运费、税费及其他费用，补齐外币汇率，逐项确认金额并确认成本完整。
6. 在“经营统计”按订单日期和客户查询，分币种查看已确认成本、暂估结果及构成订单。

## 产品与供应商

- 产品编号代表一个 SKU，不区分大小写且不可重复（含归档产品）。编号、名称、计量单位必填。规格参数为明确的名称/值，名称不区分大小写去重，最多 30 个参数。
- MOQ 最多 9 位整数与 3 位小数，必须大于零，单位同产品。未知留空，不显示成零。交期为最少/最多天数及起算说明，范围 0–3650；新交易默认确认订单后，既有档案的“收到订金后”等含义保留并随报价快照带入。产品与知识库的单一天数视为同一天数上下界，未知留空。
- 复制客户资料包含编号、名称、规格、单位、MOQ 和交期，不含内部备注。
- 归档可恢复；新报价不提供归档产品。历史报价修订可保留已使用的归档产品，产品档案修改不改写历史交易快照。
- 供应商名称不区分大小写去重；一个主联系人，联系方式与地址可选。
- 每个产品/供应商组合只保存一条供货关系；已解除关系通过编辑恢复，不再新建重复项。参考价最多 4 位小数，标明币种与报价日期；未知价留空。MOQ 与交期可独立于产品通用资料。
- 供货条件保留当前值。档案归档和解除关联不删除历史引用，既有订单成本不会跟随参考价格变化。
- 交易流程不增加附件；已有产品知识库继续提供资料关联。本版不包含多级变体、库存或采购订单。旧询盘和样品的产品自由文本保持原样，不自动映射档案。

## 报价与精度

- 结构化报价继续写入原客户报价历史，另存不可覆盖的版本快照，不建立互不相通的报价系统。编号为 `QT-000001-R1`；商业修订追加 `R2` 等版本，只能从最新版本继续修订。
- 每份报价 1–100 条产品明细。选品带入产品资料，允许对本次交易调整，不改变产品档案。数量最多 3 位小数且大于零；单价最多 4 位小数且非负。低于 MOQ 可保存，但详情和 PDF 明确提示需要确认。
- 币种沿用 USD、CNY、EUR、GBP、JPY。前四种最终金额为 2 位小数，JPY 为整数。每行按数量 × 单价计算，四舍五入到币种最小单位后再求和。
- 合计 = 行金额之和 − 折扣金额 + 向客户收取的税费 + 向客户收取的运费。折扣不能超过商品小计；税费和运费填写明确金额，不自动判断税率或贸易责任。
- 金额、数量与汇率通过 IPC 传递十进制字符串，Rust 使用定点整数及宽整数中间值计算。每种缩放后数值上限为 9,000,000,000,000,000；行合计、订单合计及统计合计也检查上限，超限拒绝保存/计算，不截断或溢出。
- 公司抬头可设置默认值，在每次报价中保存快照；有效期和贸易及商业条款必填。客户资料、产品和报价后续修订不改变旧版本。
- 旧简单报价继续读取和编辑原有字段。通过“补齐明细生成报价”明确填写商品、数量、单价及条款，另存结构化版本并记录旧报价来源；不猜测旧金额如何拆分。旧报价沿用原有两位小数存储规则，包括旧 JPY 记录。
- PDF 从已保存的报价快照生成，按同一金额和舍入结果输出；只选取对外字段，不含供应商、采购价、内部备注或利润。中文字体离线内置；不支持的字符会显示导出错误，允许更正后重试。
- 文件保存位置由系统对话框选择；取消不写文件，写入先完成临时文件后替换目标。前端不能传任意路径、SQL 或文件内容给导出命令。

## 订单与交易历史

- 从确定报价版本以事务生成 `SO-000001` 等订单编号；保存完整客户、产品、金额和条款快照。重复点击或重试返回已创建订单，不产生重复订单。
- 同一报价系列最多一个未取消订单，首版不支持拆单。订单记录所有曾承接的报价版本，从旧版本重试仍返回原订单。
- 草稿可更正订单日期、承诺交付日期、备注，并承接同系列较新报价修订；金额更正通过报价新版本完成，需要填写更正原因。承接新版本后须重新确认成本完整性；已有费用时不能直接改变订单币种。
- 状态为草稿、已确认、已取消。确认冻结订单日期和销售数据，开始纳入统计；不代表收款或履约完成。确认后仍可维护成本。
- 草稿与已确认订单可取消，必须说明原因。取消后只读，保留成本和历史，退出统计。重开须先形成未使用的新报价修订。
- 每次更正、状态和成本变化均追加带时间的完整订单快照。版本号防止陈旧表单覆盖较新修改。

## 成本与利润

- 草稿承接报价新修订时，如果移除了现有成本关联的产品，先保留原订单并提示解除该费用的产品/供货关联或更正费用，处理后才能承接；不自动删除成本。
- 每单最多 200 条费用，分类为商品采购、运费、税费和其他费用，保存原币金额、日期、备注、可选供应商及订单内产品。
- 调取供货参考价时，按该订单行数量计算采购金额，生成可编辑且未确认的草稿；必须核实实际采购成本。后续供货价修改不改变订单已存金额。
- 以订单币种核算。跨币种须手动填写汇率及日期，方向固定为 `1 费用币种 = X 订单币种`。汇率最多 6 位小数，大于零且不超过 1,000,000；转换后每笔费用按订单币种最小单位四舍五入。
- 外币汇率与日期可同时留空，标记待补全；不能默认 1:1，也不直接相加。只要有费用缺汇率，费用合计与利润均待计算。
- 收入取订单报价合计。利润 = 收入 − 商品采购 − 支出运费 − 支出税费 − 其他费用。已含在采购成本中的运费或税费不能重复录入。利润率 = 利润 / 收入；收入为零时利润率不适用，亏损保留负值。
- 人工逐条确认金额，再确认全部成本已录齐，填写完整确认说明。没有费用且未确认时利润待计算；明确确认全部为零后才按零成本计算。部分费用已录入且汇率齐全时仅显示暂估利润。
- 成本变动与利润重算在同一事务中完成。缺失汇率即使成本金额已完整确认也不产生最终结果。
- 这是订单经营测算，不是已收款、现金流、税务利润或完整会计系统。本版不实现退款、退货与跨期冲减。

## 期间统计

- 使用订单日期，开始与结束日期均包含，支持选月份及客户。只统计已确认订单；草稿、取消、报价均不计收入。
- 币种分别汇总；不跨币种混加，也不使用当前汇率重估历史订单。
- 显示纳入订单数、成本未完整数、汇率缺失数；分组展示“成本已完整确认”“暂估，成本未完整”，缺成本或汇率而无法计算的订单不被当成零成本加入利润。
- 每组利润率按该组总利润 / 该组总收入计算，不平均订单利润率。空期间与零分母有明确显示。
- 分组可下钻，明细与合计使用同一次查询、相同范围及订单快照。更正订单或成本后重新查询，不维护另一套容易失配的统计余额。
- 本版交付界面统计，不包含报表文件导出。

## 迁移与边界

schema 2 → 3 → 4 在同一 SQLite 事务中依次建立产品知识库、扩展交期上限并新增供应商、供货关系、报价版本、订单和更正历史表。已使用 schema 3 产品知识库的数据库只追加 schema 4；产品 ID、交期含义、知识资料与原件保持，交易与知识库共用产品主数据。迁移失败全部回滚，重试启动不清空数据，高版本拒绝降级。业务仍为个人单机、本地优先、无 AI、无云同步、无遥测；不获取在线汇率或自动发送报价。

历史简单报价只能补齐为一个结构化报价系列；后续从该系列最新版本修订。不同窗口同时补齐时，事务只允许一个转换成功，同一保存请求重试返回已有版本。
